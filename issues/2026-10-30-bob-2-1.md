# A new module's files have no legal moment to enter build/modules.json: the format check refuses a path naming no file, the ownership check refuses a file outside the paths

**The flaw.** A new module's first files have no legal moment to enter `build/modules.json`. The ownership check (`checks/ownership.mjs`, `checkOwnership`) fails any file of a job's diff outside its module's `paths` and `tests`; the format check (`checks/format.mjs`) fails a `paths` or `tests` entry that "names no file or directory in the product". So the files a job will write cannot be in the map before the job writes them, and the job cannot write them unless they are in the map.

**Measured.** 30 Oct 2026, tranche N2 of the process built under itself, layer 1: `build/modules.json` on `tranche` gave platform no `tools/platform.mjs` and record no `tools/record.mjs`, which the plan's entries N2-1 and N2-5 name; both jobs asked (asks A1 to A3). With the entries added, `node checks/run.mjs .` at the tranche tip reports `format: 5 failures` (the five entries naming no file) until the jobs merge. The gate compares a pull request's check reds with its base and counts only new ones (`runGate`, `tools/proc.mjs`), so the inherited red does not fail the two gates.

**Workaround in force (K1, `build/rulings.md`).** The map names a layer's files when that layer starts, and the tranche's whole-product format check stays red for those entries until the layer's jobs merge.

**Fix route.** Entry N2-45 in the architecture module's START (layer 2, `build/plan/current.md`): the format check reports such an entry as pending while the module's job is live on the state branch, and fails it only once the layer has closed.
