# The CI gate reads the module from the diff and refuses every extraction: an extraction's diff touches its legacy module too (REQ 9)

**The flaw.** The CI gate (`.github/workflows/gate.yml`: `proc gate --product . --base HEAD^1`) reads the job's module from the diff (`moduleOfDiff`, `tools/proc.mjs`) and refuses when the diff touches more than one module. Every extraction touches two: the module being built and the legacy module it is moved out of (REQ 9: the moved code removed, its callers rewired). So no extracting job could pass the gate.

**Measured.** 30 Oct 2026, tranche N2 layer 1: the gate on pull request 127 (platform) refused three tips in a row, `REFUSED: the diff touches several modules: platform, proc-legacy (one job, one module; P8)` (runs 41125538395, 41125591146, 41125660078); on pull request 128 (record), `proc-legacy, record` (run 41125229336). Reproduced on both branches' diffs against the tranche tip `973ce2a` with `moduleOfDiff` in a session.

**Blocking (MNT-8).** Decided by the architecture session: a stop (MNT-4), the fix on `tranche` with a fixture test, both layer-1 jobs given the chance to complete under the fixed version (JOB-4: complete-allowed; no work abandoned), the pin moved once to the fix commit, resume. Ruling K2, `build/rulings.md`.

**The fix.** `moduleOfDiff` drops from the touched modules any module named in another touched module's `from`: an extraction's legacy sources are not a second module. Fixture: `tools/test/proc.test.mjs`, "K2". The gate module's job (N2-23, `tools/gate.mjs`) carries it forward.
