## R14 · 2026-10-27 · Planned: a test run never gives "no result" without its cause; a runaway test fails itself; `proc tests` for a pass
- **Asked** (Bob through BOB #317, 00:36: "have it fix the process so that it doesn't happen again"): in T51b R1's zone pass, BOB's hand-written runner (a copy of `runTests`) got no summary from 8 of 82 suites. Causes BOB measured: (1) out-of-memory kills by the container's memory cgroup (about 15 GB, shared by every process): one file, bio `screens-inquiry/fr28-document.test.mjs`, alone reaches 12.6-12.9 GB (a product defect: BOB places it as a job); concurrent suites made the kernel kill other suites' runners. (2) Once, an incomplete report with exit 0 (`scheduler`, report ending at result 147 of 185), not reproduced; suspected `--test-force-exit` with a piped report. Today `runTests` turns a missing summary into `fail 1, tests NaN`, and merge and job complete refuse with no cause.
- **Measured here:** node's TAP reports a test file whose process dies as `not ok - <file>` with `signal: 'SIGKILL'`, or `SIGABRT` plus "JavaScript heap out of memory" when a heap cap stops it, so a runaway file can fail by itself, named, while the run goes on. Only the runner's own death, or a cut-off report, loses the summary.
- **The fix, in `tools/proc.mjs` (one runner for merge, job complete and the new command):**
  (a) Every run's report goes to a file (`.git/civicos-runs/`, never a pipe), and its result says **NO RESULT: <cause>** apart from failed tests: exit code and signal, timed out, the memory cgroup's OOM-kill count before and after (cgroup v2 `memory.events` or v1 `memory.oom_control`), the plan `1..N` against results seen, and the report's tail. A file whose process was killed or ran out of heap is a NO RESULT named by its file and cause. Merge and job complete refuse a new NO RESULT as they refuse a new red, with its cause; an old one is inherited like an old red.
  (b) Memory: each test process gets a heap cap (`--max-old-space-size`, default 4 GB or a quarter of the container's memory, whichever is less); files run at a concurrency the memory allows (at most 60 % of it under caps); suites run one at a time; each file's peak memory is recorded, and files above half the cap are listed as heavy.
  (c) `proc tests --modules a,b [--users] [--base <ref>]`: the named modules' suites, and with `--users` every module that uses one of them, each run singly on HEAD and on the base (default the tranche on origin); only new reds and new NO RESULTs count, as merge judges. The checkout must be clean (the pass committed locally, nothing pushed).
  (d) An incomplete report with no kill and no timeout (cause (2)) is re-run once and recorded as such; proc never uses `--test-force-exit`, and a suite that hangs is stopped at its timeout (default 30 min) and reads NO RESULT: timed out.
