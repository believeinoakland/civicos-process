# The dry run that certifies neoProcess (P3)

**Status** · Draft, neoProcess #3, 2026-10-29. The rows it proves are in `PROTOCOL.md` §10, `JOB-LIFE.md` §13 and `DESIGN-STAGE.md` §5; each becomes a row of the toy's `CERTIFICATION.md`. This file says what the run needs and in what order it goes.

## 1. What it needs (Bob's acts, P17): done 29 Oct

A toy product repository of its own, `believeinoakland/neoprocess-dryrun` (the toy lives in `dryrun/` here, but a product's `CLAUDE.md`, skill and workflow sit at a repository root, and a ruleset targets a repository's branch). Bob made it 29 Oct, public under his personal account; GitHub offers a merge queue only on a repository owned by an organization, so there is none and the tool merges (JOB-LIFE §1, §6, decided by #5 from what it measured there, §12). On it, once, by Bob: the ruleset on `tranche` (no force push, no deletion; its required check `gate` removed, because a required check refuses every direct push, SETUP-STEPS) and the one on `main` (a pull request required); no auto-merge, no secret: the process repository is public (Bob's act, 29 Oct). The seed was pushed to `main` by #5 the same day (SEED step 5). Everything below the rulesets was rehearsed on fixture tests first (`tools/test/neo*.test.mjs` run the whole life against a real git remote).

## 2. The order

1. **Seed.** As `n1/SEED.md` says, step by step: BOB clones the toy repository, copies `dryrun/` into its root and `n1/overlay/` over it (the requirements written ahead with `*(not yet met: N1)*` marks, the canon of the two areas, `build/areas.md`, the two area rulebooks, the manifest), removes the old mechanics' runs, runs `neo shims`, pushes `main`, and opens the tranche with `n1/plan.md`: every entry drives a row of `n1/CERTIFICATION.md` (one row per path of PROTOCOL §10, JOB-LIFE §13 and DESIGN-STAGE §5, each naming its driver and its evidence). The seeded toy was built in a scratch directory on 29 Oct (#4): the checks green, 20 module tests green, every START under 4 KB.
2. **Open.** From the toy's BOB session (`/neoprocess bob`): `neo epoch open`, `neo takeover`, `neo lane open` for ARITH (started at once) and STATISTICS (left dormant: its first ask starts it, row P19; two lanes because one row is a lane's question to another lane through BOB), `neo layer start --layer 1`; the printed PR and session calls, one by one, each recorded by its `neo` command.
3. **Run the rows.** Each row is driven by an entry or by an act of BOB's (listed at the end of `n1/SEED.md`) (a refresh with a `Working` line out, a lane past half its window, a killed worker, a message before its push, a duplicate number), and proved by what git and GitHub show, never by a session's report (P20): the ask file's stages, the PR's comments and checks, the state branch's lines, the metrics rows. The account move row is recorded as §15 allows, between Bob's two real accounts only.
4. **Close.** `neo layer close`, the archives, `neo epoch close` (the state branch gone, every durable file on `tranche`), the close PR to `main` merged by BOB with the plan reading CLOSING; `CERTIFICATION.md` with one row per proof, each naming its evidence.
5. **The commit point.** Only when every row holds: `neo` takes the `proc` name, the old tool, skills and mechanics are rewritten from the lane's files, and the rulebooks move to `rulebooks/`.

## 3. What is measured only here (JOB-LIFE §12)

The tool's merge on `tranche` (JOB-LIFE §6): the gate on a pull request, a branch behind the tranche updated by `update_pull_request_branch` and the gate run on it, the merge by the printed call, the `pull_request.closed` event after it. (Whether a `/goal` message sets a goal again after a wait was measured on 29 Oct: it does not, SESSIONS §1b.)

## 4. Flaws the run found (P3: each fixed in the tool before the run went on, with a fixture test)

1. **An empty pull request is refused** (BOB #1, R-BOB-1-1, SEED step 8): GitHub refuses a PR with no commit between base and head, and `layer start` made job branches at the tranche tip. Fix `b3ff809`: an opening commit on every job branch; a START made and not yet opened is remade by the same call; the gate reads an empty diff as nothing yet.
2. **A lane started before any ask could not meet its goal** (ARITH #1 via BOB #1): the goal named an ask, and no command recorded a lane's wait. Fix `cba1554`: `neo lane state --set`; the goal is met with no ask open, so such a lane idles until a message.
3. **The proxy refuses every remote ref delete** (BOB #1, R-BOB-1-2; confirmed by #5 on a probe branch: `unexpected disconnect`, the branch kept). Fix `164445b`: no command deletes a branch; a job branch is remade by an opening commit over what is there (a merged tip takes both parents); `merged` and `epoch close` print the dispatch of the product's `prune.yml` (`workflow_dispatch`; `state/*` and merged `job/*`), measured on the toy: run 40827749216 deleted `job/probe` in 11 s. Leftover toy branches `seed-*`, `probe-delete` are Bob's to delete in the UI; harmless.
4. **A re-dispatch could not be recorded** (BOB #1, row P10): `ask dispatch` refused while work was out. Fix: `--again [--why]` re-dispatches from the recorded brief, the replaced Working line kept under the new one.
5. **The gate's base in CI was the event's base sha** (BOB #1: PR #4's ownership failed on a file alpha never touched, the tranche having moved between the event and the run). Fix: `--base HEAD^1`, the merge ref's own first parent; the shims on `tranche` regenerated by BOB.
6. **J8 had no driver**: plan N8 asked beta's test to copy alpha's error words, which BLD 5 forbids (BOB #1's A3 answered that the test reads them at run time). J8 is redefined as the update-and-rerun mechanism (CERTIFICATION); a red on the merged result is J3's path.
7. **A job waiting on another's merge could not end its turn** (BETA #1's REPORT 2): `ready after <m>` sat in the job's owed list and its Stop hook counted it. Fix: it is BOB's act (cleared by `neo merged`), left out of the job's gate; the job's COMPLETE message says it waits.
8. **A review could not be posted** (BOB #1, R-BOB-1-3): GitHub refuses REQUEST_CHANGES and APPROVE on one's own pull request, and every session is Bob's one user. Fix: the review is posted as a COMMENT review carrying the verdict; the approval the merge reads is the Review line.
9. **The metrics row's `reviewed` read the last Review line** (BOB #1, at layer 1's close: alpha's reviewed runs counted `no` after its unreviewed re-open). Fix: the job line keeps `Reviews` and `Merges` (each merge with the review count then), and the row reads `reviewed merges/merges`; alpha's N1 row stands as written (`no`), noted here.
10. **A lane id equal to a module's name** (BOB #1, R-BOB-1-4: lane `STATS` against module `stats`): session names `<ID> #k` are one namespace for jobs and lanes, and the hook read the job `STATS #1` as the lane's. Fix: `neo lane open` refuses such an id; the seed's lane is `STATISTICS` (BOB #1 closed STATS and opened STATISTICS); `--dormant` opens a lane with no start owed.
11. **A dormant lane's start was not owed by `ask ask`** (BOB #1, R-BOB-1-5), so the hook refused the printed create_session. Fix: `ask ask` owes `start lane <ID>` when it prints the start; `lane route` is the recovery for an ask already ASKED.
12. **A closed lane's id still named a lane in the tool** (BOB #2, R-BOB-2-1: `ask close` routed the reply for STATS #1 to the closed lane STATS). Fix: only an OPEN lane's id is a lane, in `ask route`, `ask close` and `lane open`'s session text; the hook already read it so.
13. **A job's clone started on a detached HEAD** at its branch's tip (STATS #2, R-STATS-2-1): `job start` refused, and the hook refuses a checkout before a role is recorded. Fix: the start commands (`job start`, `lane start`, `takeover`) make the branch at a detached tip themselves.
14. **A BOB blocked on Bob was looped by its goal** (BOB #2, 08:08–13:45Z: 588 goal iterations, a command each turn, so the evaluator never stopped): the START's goal named no wait state for BOB. Fix: the goal counts a queue holding only NEEDS BOB / RELAY TO BOB items, relayed to the lane, as met (START-BOB.md); the rule for every role's goal (SESSIONS §1b): a wait that is another party's to end is a terminal state.
15. **A toy's detail was routed to Bob and the run waited five hours** (A4, rows P4/D3; Bob, 29 Oct: "you should not be stopping to involve me in these details… figure out why you are and fix it"). Three causes: the rules read every change of a requirement's meaning as his (DES 1, REQ 6, GOV 1–2, PROTOCOL §4.3, DESIGN-STAGE §2.2 now carry the narrower test: what the product does for its users, unanswered by the canon; a doubtful case is BOB's, decided and reported); the dry run's plan (N11) and rows scripted a decision of his where the toy's owner is the lane (the lane decided A4 and the rows prove the mechanism); and the lane's habit of ending turns "waiting on Bob" and listing housekeeping as his acts (the handoff's list cut to acts only he can take, none of which the work waits on). Bob's requirement (29 Oct): the process overcomes that habit strongly and consistently; enforced by code: `proc ask route --bob` refuses without `--users` and `--canon-silent` (DES 1's test), BOB's and a lane's Stop hook refuses a turn ending on words waiting for Bob, every role's goal counts a wait as terminal; P19 carries his words.
16. **The tranche's last BOB had no home for its row** (#5, 29 Oct, foreseen before the close): `bob archived` writes `build/metrics/<T>.csv` on `tranche`, and the last BOB is archived by ROOT after the close PR merged, when `main` holds the tranche whole and a push to it would make the next `tranche open` refuse. Fix: `bob archived --tranche <T>` is run by the next tranche's BOB, under the closed tranche's id (rulebook USE 2: "a BOB's written by its successor under the tranche it worked in"); refused on a closed tranche; a session's second row refused. N1's last BOB, with no next tranche on the toy, is recorded in §5.
17. **BOB #2 ran to 67 % of its window** (neoProcess #6, 29 Oct 14:18Z, `get_session`: 674,896 of 1,000,000 tokens, 691 M cache-read tokens in all; the threshold is 40 %, P13, rulebook SES 5): BOB's own threshold was text, and nothing in the run read it. Fix: every role's Stop hook reads the context from the transcript (the last assistant turn's input, fresh, cache read and cache write) and, past 40 % for BOB or half for a job or a lane, refuses the turn's end until the refresh is recorded: BOB's by `neo handoff` (which marks it for the session), a job's or a lane's by the wait `BLOCKED: context`, which BOB's queue lists as UNBLOCK and answers by `job route` / `lane route`. BOB #2 was told to hand off at once.
18. **A BOB that had handed off was sent back by its goal** (BOB #2, 14:20–14:23Z: 28 iterations in all, each a turn re-reading about 720 K tokens; 735 M cache-read tokens at the end against 691 M at 14:16): its goal named the run's end and a wait on Bob, not a handoff, and the lane's archive and interrupt of it were refused (§5). The loop ended by itself once its turns used no tool. Fix: every BOB's goal counts its handoff, made by `neo handoff` and its START sent to ROOT, as met (START-BOB.md; SESSIONS §1b); a refreshed job or lane is already terminal (`BLOCKED: context`, §4.17).
19. **A refusal could not be routed after the last round** (BOB #3, 14:28Z: `refused routed` for R-NEOPROCESS-6-1 printed `build/plan/current.md: no running plan`): the metrics row took the tranche id from the running plan, which the last `round close` removes. Fix: `refused routed`, `defect` and `bob archived` take the id from the running plan or, between rounds and after the last, the archived one.
20. **The close PR could never merge** (BOB #3, 14:34Z, R-BOB-3-1: the hook refused the printed `merge_pull_request` of PR #11 "N1: close"): the hook let the one merge at CLOSING pass only with `base === 'main'`, and the merge tool's input carries no base. Fix: `tranche close` prints the merge call with `expectedHeadSha` the tranche's tip, and at CLOSING the hook passes exactly that (method merge, the expected head the tranche's tip on origin), nothing else; a job branch's head is never that tip.
21. **A refusal made at CLOSING cannot be routed** (BOB #3, R-BOB-3-1, 14:40Z): routing writes its metrics row to `tranche`, and after the close PR merges nothing is pushed there; the state branch that held the record was then deleted. Fix (the commit point, with tests): a refusal is routed before the close PR merges, so its row rides the PR: BOB's hook refuses the close merge while a refusal is OPEN, naming it, and `epoch close` refuses while one is OPEN; between the merge and the epoch's close the only acts are the tool's own, whose one refusal (the delete) it handles itself. R-BOB-3-1's record is in `dryrun/N1/CERTIFICATION.md`.
22. **The lane that maintains the process could not start under it** (neoProcess #7, 29 Oct, after the commit point): CLAUDE.md sends every session to the skill, whose hooks refuse every act until a start command records a role; the three start commands need a product's state branch, which the process repository does not have, so the neoProcess lane was refused every edit, push and tool call (and the safety classifier, rightly, refused the session writing its own role record by hand until Bob approved it in words). Fix, with a test: the role `process` and its start, `proc process start --branch <b> --session <id>`, which records the lane's own branch, pushes only there (never `main`, a state branch or a force), lets the lane open and merge its own pull request (no BOB in the process repository), starts no session, reads the lane's rulebooks, and refreshes at half its window by its handoff (`proc process handoff`). No product path changed (the suite's other 263 tests unchanged); the path is proven by #7 itself, which started and worked under it.
23. **The tool's own HTTP reached no credential** (neoProcess #7, 29 Oct): Node's `fetch` ignores the session's proxy unless `NODE_USE_ENV_PROXY` is set at its start, so `proc repo setup` would have answered 403 whatever token Bob set (`GET /user` 403 without, 200 with, measured). Fix, with a test: `proc` restarts a network command with it set (`repo setup`, `grants check`).
24. **A commit message was read as a push** (neoProcess #7, 29 Oct): the hooks took the word `push` anywhere after `git` for the subcommand, and refused a commit whose message said "push". Fix, with a test: a push is `push` in git's subcommand position, after git's own options.
25. **The onboarding check judged the wrong repository and the wrong branch** (the convert dry run, below): `init --check` ran its drift check in the current directory when called without `--product`, and against this checkout's branch rather than the one the project follows. Fix, with a test: it checks the project itself, against the branch its own `CLAUDE.md` names.
26. **The tool's repository creation could not run from a session, whatever token** (neoProcess #8, 29 Oct, X9): in a new session on the process repository alone, the classifier let `proc repo setup` run, and the proxy itself refused `POST /user/repos` (*sessions are bound to their configured repositories*), as it refuses settings writes (#5); the GitHub MCP server's create answered GitHub's 403 for the Claude app; the process's token, set by Bob on the environment, never reached the API (`GET /user`: the app's client id). Fix, with a test: the writes run on GitHub's runner, by the process repository's workflow `repo-setup.yml` with the token as its Actions secret; from a session `repo setup` reads, and prints the workflow's dispatch and Bob's hand steps; on the runner it writes.
27. **The lane's refresh needed Bob** (neoProcess #8, 29 Oct; Bob: "aren't you at the point … that you can refresh yourself without my involvement?"): the lane's start (§4.22) left its successor to Bob, from a START file, because the hooks let no role but BOB and ROOT start a session (SES 1) and the lane has no parent session in the process repository. Fix, with a test: `proc process handoff` writes the successor's START file (for a broken chain) and prints its `create_session`; the hook passes that call, unchanged, for the role `process` and nothing else; the successor is the predecessor's child (depth +1; at depth 8 Bob restarts the chain, SESSIONS §2). The classifier refused the lane's first edit of its own hook as self-modification; the same edit through the editor tool, in the open, passed.
28. **The seed's shims were product files to the architecture check** (the new-path dry run, below, #9): `proc init` wrote `not_product` as `build/` and `requirements/` only, so the product's first checks failed on `CLAUDE.md`, `.claude/` and `.github/` as owned by no module, and its first gate would have. Fix, with a test: the seed's `not_product` is `NOT_PRODUCT` (the build state, the canon, the shims, the root README).
