# Seeding the toy repository for N1 (DRYRUN §2.1, expanded)

Done by the dry run's BOB (on the toy's `main`, before the tranche opens), once Bob's setup act exists (`SETUP-STEPS.md`). `<proc>` is this process repository's checkout; `<name>` its GitHub name as it is then (`believeinoakland/civicos-process`, or `neoProcess` after Bob's rename).

1. Clone `believeinoakland/neoprocess-dryrun` (empty) and, inside it, copy `<proc>/dryrun/` to its root, then `<proc>/lane-neoprocess/n1/overlay/` over it (the overlay replaces `build/modules.json`, `build/manifest.md`, the three requirements files, and adds the canon, the areas and the two area rulebooks).
2. Remove what belongs to the old mechanics' runs and not to this product: `build/plan/current.md` and `build/plan/archive/`, `build/jobs/`, `build/metrics/`, `cert/`, `d6/`, `RUNS.md`, `CERTIFICATION.md`. Then copy `<proc>/lane-neoprocess/n1/CERTIFICATION.md` to the root (every row PLANNED).
3. `node <proc>/tools/neo.mjs shims --product . --process <proc> --repo <name>` writes `CLAUDE.md`, `.claude/skills/neoprocess/SKILL.md` and `.github/workflows/gate.yml` (the workflow carries the same `--process` and `--repo`, so CI's drift check regenerates the same text). If Bob made the process repository public and no `NEOPROCESS_DEPLOY_KEY` exists, the workflow's `ssh-key` input is empty: whether the checkout action then falls back to its token is unmeasured, and the first CI run measures it (JOB-LIFE §12).
4. `node <proc>/checks/run.mjs .` is green (format, architecture, coverage; the ids marked `*(not yet met: N1)*` count as written ahead once the plan is current, step 6). `node --test alpha/test/*.test.mjs beta/test/*.test.mjs stats/test/*.test.mjs` is green.
5. Commit everything as `main` and push it (`git push -u origin main`): the one push to `main` the toy ever takes by hand, before any tranche exists.
6. `node <proc>/tools/neo.mjs tranche open --product . --plan-file <proc>/lane-neoprocess/n1/plan.md` makes `tranche` from `main` with the plan current; `neo epoch open`; `neo takeover --name "BOB #1" --session <id>`.
7. `neo lane open --id ARITH --area Arithmetic --charter-file <proc>/lane-neoprocess/n1/charter-ARITH.md --canon requirements/arithmetic.md,.claude/rules/arithmetic.md`, then the printed `create_session` and `neo lane started`. The same for STATS with `charter-STATS.md` and `requirements/statistics.md,.claude/rules/statistics.md`, but STATS is NOT started: its first ask starts it (row P19).
8. `neo layer start --layer 1`: the printed PRs, sessions and `neo job pr` / `neo job started` calls, one by one. The run is on.

What BOB injects while it runs (each a row): re-charter ARITH once by `neo lane charter` (P7); dispatch one reply with `--due 1` and let the backstop list it LATE (P11); kill one worker with TaskStop and re-dispatch from its brief (P10); run `neo ask decided` twice for one ask (P12); route STATS with `--context-pct 60` while its ask reads ASKED (P13); hand over to BOB #2 while a `Working` line is out and an ask reads ASKED (P5, P14); time the reply to alpha's `QUESTION #1` after alpha has merged, so the fold is a `CHANGE` that re-opens it (J7); retire alpha by `neo job retire` once beta has merged, and let `layer close` retire beta (J9); close the epoch at the end and open the next (P20, D4).
