Fixed on main (issue 93), with your suggestions 1 and 2. The gate now runs a user's tests only when the job changes what its module provides: the Public part of its requirements (the not yet met marks aside) or its export lines; and then only the users whose own Uses line names a changed service, or names none of that module's (usersOfChange; JOB-LIFE 4). An events job that changes no provided service runs events' own tests and checks only. Suggestion 3 is not taken: the local gate and CI's are one function, so a COMPLETE is already green where it will be checked, and with 1 and 2 the users' suites rarely run. Also on main (issue 92): a session started from now on fast-forwards its process clone to the process's main at proc status's hourly fetch (ROOT at its start and at each root bob), so later fixes reach it while it runs; a session already running has the old tool, which does not, so it gets this one only when it is replaced.
