# REP · Repository & tooling · what lives in git, what leaves it, and what guards it

In force from 2026-10-29, certified on N1. At most ten rules, one screen, each checkable. Tags: YOURS (Bob's policy) or BOB'S; CODE names what enforces it, TEXT means nothing does.

1. The branches are `main`, `tranche` (made from `main` once, never deleted, fast-forwarded to `main` at each tranche's open) and `job/<module>` (made at the tranche tip, deleted by the tool once merged, remade by a re-open); `main` never moves while a tranche runs. (P10, P12; JOB-LIFE §1) BOB'S · CODE: `proc` makes, moves and deletes them; the ruleset refuses a force push or a deletion of `tranche`; BOB's hook refuses any push to `main`.
2. No session force-pushes, rewrites history, deletes a remote ref by hand, pushes a tag or touches `snapshot/*`; the tool alone deletes a merged job branch and a closed epoch's state branch, whose every object is elsewhere; the standing list never loosens this. (P12, P16; Bob, K1261, K2254; PROTOCOL §7d) YOURS · CODE: every role's PreToolUse hook; the git proxy refuses hand deletes and tags.
3. A job pushes only its own branch, and its work reaches `tranche` only through its pull request, merged by the tool; BOB and a lane push `tranche` for what is no job's (the plan, prepared requirements, a lane's fold); only its owner writes a mail branch. (P7, P12, P18; JOB-LIFE §4, §11; mechanics: the cross-account channel) BOB'S · CODE: the hooks; `proc merge`; the channels check.
4. Dead branches are deleted only by the `prune-branches` workflow, never `main`, `snapshot/*`, `study/*`, `mail/*`, `dist/*`, an open pull request's head or an open tranche's `job/*`. (P12, P17; Bob, K5300) BOB'S · CODE: `.github/workflows/prune-branches.yml`.
5. Transient state lives on the orphan branch `state/<epoch>`, durable records on the tranche branch, each path on one only; nothing durable cites the state branch and nothing merges, tags, branches from or opens a pull request on it. (P13, P15; Bob, 29 Oct; PROTOCOL §7d) BOB'S · CODE: `proc epoch open|close`; the tool and the hooks refuse each.
6. Screenshots and other captures never enter git: they go to the product's object storage with a 30-day expiry, and the report, with the keys, goes to the tranche branch. (P13; Bob, 29 Oct; PROTOCOL §7d) YOURS · TEXT.
7. A job never commits a generated artifact; the gate regenerates every listed one for its run and fails when one does not verify, and `proc layer close` regenerates and commits them once. (P7, P12; JOB-LIFE §4) BOB'S · CODE: the gate; the ownership check; `proc layer close`.
8. A session starts on a shallow clone of its own branch; the tool fetches older history only when a step needs it. (P13) BOB'S · CODE: `proc job start`, `job complete`, `layer close`, `gate`.
9. Hooks come from the role's skill. The standing list is one file, the process repository's `permissions.json` (Bob's approval of 29 Oct), from which `proc shims` writes each product's `.claude/settings.json`, allow and deny; the hook answers `allow` only for the role's acts of the act table; nothing in either loosens rule 2. (P16, P17; PERMISSIONS §2.4, §6, §8) YOURS (the list) · CODE: `proc shims`; the gate fails on drift; the hook.
10. A refused act is recorded by `proc refused` and routed from the act table (`tools/acts.md`), never worked around, split or retried; an unpredicted refusal in a product run stops the work until the table and the route are fixed. The rulesets (no force push, no deletion; a pull request on `main`) are Bob's one setup act per repository. (P3, P16, P17; PERMISSIONS §2; SETUP-STEPS) YOURS · CODE: `proc status` lists REFUSED and BOB's turn cannot end with one open; `proc refused routed` counts it.
